> 本目录是**可复用模板**，供编剧·分镜 agent 在确认集号后复制为 `assets/EP-XX/01-script/` 直接产出第一稿。
> 契约来源：[PIPELINE-DESIGN.md](../../../PIPELINE-DESIGN.md) §1–3、[TASK-SPEC.md](../../../TASK-SPEC.md) §4/§7/§10、[COLLABORATION.md](../../../COLLABORATION.md)。
> 铁律：不擅自改编剧本情节；每条旁白都要能对应到具体画面要素；不跳 checkpoint。

## 0. 步骤契约（来自 PIPELINE-DESIGN §1）

| 项 | 内容 |
|---|---|

## 1. 解说词质量标准（来自 TASK-SPEC §4 / §7-01）

- **口播体**：能直接念出来、自然连贯，不是书面剧情梗概。
- **讲清三件事**：人物关系、事件因果、情绪变化。
- **保留关键对白与情绪点**：原剧本关键台词用引号保留，并标注情绪。
- **按集切分**：只做本集，不串剧情。
- **画面可对应（留口）**：每个旁白节拍留出「画面要素提示」位，交给步骤 02 细化（人物/动作/场景/证据）。

## 2. 归档与版本规则（来自 PIPELINE-DESIGN §3）

```
assets/EP-XX/01-script/
├── README.md            ← 本文件复制版（本集说明）
├── v1/                  ← 版本目录（不满意→v2，保留历史可回退）
│   ├── narration.md     ← 产出：解说词正文（核心交付）
│   ├── prompt.md        ← 本次产出用的 prompt / 改写思路
│   ├── params.json      ← 模型/集号/来源语言/版本/保留对白数 等
│   ├── meta.md          ← 说明：字数/预估时长/取舍/待确认项/失败原因
│   ├── refs/            ← 参考依据：用到的英文/中文剧本节选片段
│   └── output.*         ← （可选）导出文本/txt
└── latest               ← 通过 checkpoint 的最新版本指针（README 行或软链）
```

- 每个版本一个目录：`v1`、`v2`…，历史版本保留以供回退与复用。
- checkpoint 通过的版本标记为 `latest`（在 `README.md` 写一行 `latest → vN`，或软链）。
- 跨集复用：本步骤无跨集基准资产（那是步骤 03 的事）；**角色/关系速览抽成跨集单一事实源 `assets/_shared/characters.md`**（EP01 定稿后 EP02/03 直接继承，步骤02 分镜 + 步骤03 资产都以它为基准）。

## 3. 如何使用本模板（DOCX 一到就开跑）

1. 复制本目录到 `assets/EP-XX/01-script/`（`EP-XX` = 确认的集号，如 `EP-01`）。
2. 读英文版剧本本集（主）+ 中文参考本集（理解剧情/人物关系）。
3. 把 `v1/narration.md` 填成口播体解说词；`v1/refs/` 放用到的剧本节选。
4. 填 `v1/params.json`、`v1/meta.md`、`v1/prompt.md`。
5. 用 `CHECKPOINT.md` 的格式把 v1 摆给 maozh2（经总控）确认。
6. 通过后写 `latest → v1`；不通过则开 `v2`，保留 v1。

## 4. 待确认规格对产出的影响（TASK-SPEC §10）

下列项未确认前，本模板按**保守默认**产出，并在 `meta.md` 显式标注，规格定了再校准：

| 待确认项 | 默认假设 | 校准影响 |
|---|---|---|
| 旁白/字幕语言 | 中文旁白 | 语言切换需重写 narration |
| 单集时长 | 约 1–2 分钟 | 字数上限决定旁白密度 |
| 画幅 | 竖屏 9:16 | 不影响 01，主要影响步骤 02+ |
| 改编边界 | **保守：只做必要口语化，不改情节/不删关键对白** | 任何压缩/删改须在 narration §4 标注并等确认 |
